# Demo runbook

Use the [canonical three-minute speaker script and ten-slide storyboard](../presentation/STORYBOARD.md) with the [PowerPoint](../presentation/CUTLINE-3-minute-pitch.pptx) or [PDF](../presentation/CUTLINE-3-minute-pitch.pdf). Keep timing and spoken copy in that single storyboard so the deck and narration cannot drift apart. This document covers operating the product before, during, and after the pitch.

The presentation artifacts are being refreshed for the latest verified sponsor results. Use the final regenerated versions and complete their render review before presenting.

## Before the timer

1. Use the actual checked product URL. Localhost is only suitable for browser sessions on the presenter computer; a phone needs the published HTTPS room link.
2. Keep the creator browser profile open. Verify Connections after any refresh, since personal keys live only in the current tab.
3. Create a fresh train story, start Orbis, and wait for moving frames. Provider allocation happens before the timed pitch.
4. Test one simple visible cue. Inspect both its acceptance trace and the actual image. Live capacity and picture quality must be observed in the current rehearsal.
5. Enter a Nebius key or shared presenter code and confirm a scene tagged `nebius`. The recorded smoke test proves the adapter works; this rehearsal checks the current credentials and combined live path.
6. Invite the audience and test the QR/link from a second device or isolated browser profile. Ensure the phone displays the shared-screen instruction and can change its vote.
7. Close credential dialogs. Set audio deliberately and keep the stage readable. Keep a [recorded live example](../public/demo/cutline-live.mp4) ready as a clearly identified fallback.
8. If using the cosmic opening, show the original source sequence and then enter the film. Scientific frames remain intact; Orbis generates the fiction.

## Operate the live loop

| Action | Expected evidence |
| --- | --- |
| Play the cinematic opening | Labeled original source images with subtle camera motion; any connected model stays paused |
| Enter live film | The fictional story is selected; Orbis primes its take and moving frames arrive |
| Invite audience | QR and actual room link open the voting companion |
| Open audience voting | Three choices and totals synchronize across identities |
| Change a vote | One ballot changes choice without increasing that person's ballot count |
| Close voting & direct winner | Results freeze, one winner is applied, and the next direction is sent to live Orbis |
| Inspect the response | Acknowledgement and later chunk are visible; inspect the actual video separately |
| Continue from an earlier scene | The active branch changes; alternate scenes remain saved; video regenerates |
| Export | Markdown treatment, JSON graph/current poll, or ten seconds of actual upcoming player media |
| End session | The stream closes while the saved story remains in the library |

No ballots means no invented winner. Open another round when the audience is ready. A tied result follows the displayed choice order.

Keyboard shortcuts: `1–4` for the four live film cues, arrows for source chapters, `Space` for live film pause/resume, `Esc` for theater mode, and `?` for help. Source-opening playback has its own visible controls; Space does not resume hidden Orbis generation behind it.

## Recovery on stage

| Situation | Recovery and accurate language |
| --- | --- |
| Orbis allocation/capacity failure | Choose the other supported model or reconnect. If using the fallback: “This is a recording from our earlier live run.” |
| Nebius unavailable in this rehearsal | Keep the saved winner; fix Connections and apply it, or use explicitly labeled rehearsal planning. Do not call a rehearsal beat a live Nebius result. |
| Accepted command has a weak visual effect | Send one simpler visible change and inspect later frames. The acceptance trace confirms delivery, not exact visual execution. |
| Story changed in another tab | Let the latest snapshot arrive, then retry the intended action. Version checks prevent overwrites. |
| Planner failed after vote closure | The winning choice remains saved. Use Apply winning choice after recovery. |
| Audience cannot reach the room | Use the verified public URL or the prepared second-device participant. A phone cannot reach the laptop through its own localhost. |
| Recording is unavailable | Restore active playback, then record the next ten seconds. Written exports remain available separately. |

## After the pitch

End the live session, download the story if needed, and keep the recorded example labeled. Reference [VERIFICATION.md](VERIFICATION.md) for exact evidence. Do not describe a single latency observation as an average, an editorial scale transition as a measured scientific flight, or an alternate story branch as exact video rewind.
