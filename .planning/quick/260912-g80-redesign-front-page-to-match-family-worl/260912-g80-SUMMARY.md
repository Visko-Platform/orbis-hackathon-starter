# Summary: Redesign front page to match "Family World" design import

Implemented the "Family World" modernist landing page (imported live from
the Claude Design MCP project 868bef8e-ac73-4d10-8db7-6a61a92c86e8) as the
real Next.js front page, and added a Google sign-in control to the nav's
top right.

## What changed

- `my-orbis-app/app/family-world.css` (new) — design tokens (Archivo font,
  modernist red-orange accent, 0-radius) and `.fw-*` component classes,
  scoped under `.family-world` so they don't leak into `/session`'s
  existing dark theme.
- `my-orbis-app/app/components/FamilyGallery.tsx` (new) — client component
  porting the design's seed relatives (Lola/Cavite, Yay/Phnom Penh,
  Babushka/Leningrad), drag-and-drop "add someone" tile, 4-field form, and
  add/remove/toast behavior to React state.
- `my-orbis-app/app/components/GoogleSignInButton.tsx` (new) — Server
  Component using `auth()`/`signIn()`/`signOut()` from `auth.ts` via
  inline Server Actions; shows "Sign in with Google" or the signed-in
  email + "Sign out". Placed as the rightmost element in the nav.
- `my-orbis-app/app/page.tsx` (rewritten) — composes nav, hero, family
  gallery, accent CTA band, and footer per the design; front page stays
  public (middleware.ts unchanged — still only gates `/session` and
  `/api/reactor/*`).
- `my-orbis-app/public/images/phnom-penh-1964.jpg`,
  `my-orbis-app/public/images/leningrad-1980s.jpg` (new) — copied from
  `.planning/spikes/006-world-select-landing/`, the two seed photos the
  design references that weren't yet in `public/images/`.

## Verification

- `pnpm build` — compiles clean, no type or lint errors.
- `pnpm dev` + `curl` against the rendered HTML confirmed: nav renders
  "Add someone" then "Sign in with Google" (top-right-most), all three
  seed relatives (Lola, Yay, Babushka) render with their photos
  (200 on `/images/*.jpg`), the accent CTA band and footer copy render,
  and `/session` still redirects (302) through the existing auth gate —
  the new front-page styles don't affect it.
- No real browser/screenshot tool was available in this environment
  (claude-in-chrome not connected) — verification was via build +
  rendered-HTML inspection rather than a visual screenshot. The user
  should do a quick visual pass, especially the drag-and-drop add-someone
  interaction and the Google sign-in flow end-to-end (needs a live Google
  OAuth round trip to confirm fully).
