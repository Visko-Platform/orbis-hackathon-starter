**Project rule (AGENTS.md):** This is Next.js 16.3.5 and the repo warns that APIs and
conventions differ from model training data. This plan needs no new routing API — it uses

**Critical ID mismatch (the whole reason this needs care):**

- `app/explore-grandmas-world/page.tsx` `MEMORIES[].id` values are `"lola"`, `"yay"`, `"babushka"`.
- `app/components/LiveWorld.tsx` `SCENES` is keyed `"seed-lola"`, `"seed-yay"`, `"seed-babushka"`,
  with `DEFAULT_SCENE_ID = "seed-lola"` and an `isSeedMemoryId(id)` guard.
- `app/live-world/page.tsx` routes on that guard: a **non**-seed `memoryId` renders
  `<LiveWorldSession>` (a real Orbis session that expects an AddFamily-created memory in
  sessionStorage), not the curated simulation.

So linking `?memoryId=lola` would NOT open Lola's scene — it would fall through to the
live-session branch with nothing to seed it. The link must carry the `seed-` prefixed id.

**Existing button pattern to copy** (from `FamilyGallery.tsx`, the card CTA):
`<a href={...} className="fw-btn fw-btn-primary" style={{ justifyContent: "flex-start", whiteSpace: "nowrap" }}>Enter their world →</a>`

`fw-btn`, `fw-btn-primary`, and `fw-btn-ghost` are defined in `app/family-world.css`, which
the explore page already imports.

**Destination is this app.** `family-world-flax.vercel.app` is this project's own Vercel
deployment — `/explore-grandmas-world` is the route in this repo. Use a relative path
(`/live-world?...`). Do NOT hardcode the vercel.app origin and do NOT use `target="_blank"`;
a hardcoded absolute origin would break local `next dev` and preview deployments.
